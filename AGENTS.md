# Explorer Dirs project rules

## Product boundary

- Build a Windows file browsing window replacement with Q-Dir style multi-pane workflows. Do not replace the desktop, taskbar, login shell, or the `explorer.exe` system file.
- Use Q-Dir and other products as interaction references. Do not copy their binaries, configuration, artwork, or proprietary source into this repository.
- Q-Dir's published EULA prohibits decompiling, reverse engineering, or disassembling its executable. Do not analyze or disassemble Q-Dir binaries; derive compatibility from public documentation, user-provided configuration samples, and ordinary observable product behavior. Do not install a reverse-engineering provider for Q-Dir analysis.
- Keep tab, pane, layout, and file-operation behavior independently testable. Preserve existing sessions and user files when adding features.
- Each file pane uses the Windows Shell ExplorerBrowser view. Keep its native item/background hit testing and View/Sort/Group/New/Properties commands; prepend Explorer Dirs commands to the same native context menu. Do not substitute a WPF ListView for the file view without explicit product review.
- Mouse context-menu commands must use a confirmed click target, not merely the Shell selection, because a background click can leave items selected. Keyboard context menus use the Shell selection. If mouse hit testing is unavailable, omit custom commands whose target cannot be confirmed; leave the native Shell menu intact.
- Use the selected Shell item's attributes to decide whether to offer “open in new tab”; do not synchronously call `Directory.Exists` from context-menu construction. Limit that command to ordinary filesystem folders, excluding stream-backed containers.
- A tab header supports middle-click and left-button double-click to close. Keep at least one tab in each pane.
- Drag-hover activation must stop when its pane becomes hidden as well as unloaded. Consume stale timer targets and recheck loaded/visible state plus tab membership before selection; layout hiding does not guarantee Unloaded and must not activate a hidden pane.
- Recursive-size worker failures must marshal to the UI thread and validate the current scan identity before clearing cached results or reporting errors. A retired failure must preserve results from a newer scan, just as retired success/progress must not publish.
- The isolated IShellView navigation history must reject nested BrowseObject calls while a navigation callback is active. Closing during that callback aborts history commit and defers retained PIDL release until the callback exits; reject navigation after disposal. Synthetic pointer-pool evidence does not replace native Shell reentrancy acceptance.
- Isolated delayed Shell menu commands belong to an installation generation as well as a pane owner. Reinstalling/reactivating the same owner/HMENU must not revive old commands; invalidate on replacement/retirement and recheck the captured generation during deferred dispatch.
- Reading an isolated native view-state IStream snapshot must preserve its 64-bit seek position in a finally block: Shell may still hold the same writable stream and continue writing. Verify position preservation with a real native memory stream, separately from Shell SaveViewState lifecycle acceptance.
- Mark an isolated StreamViewHost retired before COM/menu cleanup and reject subsequent GetViewStateStream requests with a failure HRESULT and null output. Repeated disposal must not create/save fresh state resources; existing caller-owned stream references retain their normal COM lifetime.
- Clear the isolated host's borrowed View on retirement and reject QueryActiveShellView before AddRef after disposal. SetActiveObject must recheck retirement after invoking its handler, so reentrant closure cannot acquire a new native reference. Clearing a borrowed pointer does not release the caller-owned view.
- Isolated persisted view state uses a host-opening byte snapshot as its expected save baseline, including missing-versus-empty identity. Coordinate cooperating writers with the existing per-path mutex naming and compare under the lock before atomic replacement; preserve detected external creation/deletion/update conflicts. Opening snapshots are not live views of another host's later saves.
- Enforce native saved-state read limits using the same open file handle for length and bounded reads. Do not check a path length and then call unbounded ReadAllBytes on that path; an atomic replacement can redirect the second open to unchecked content.
- Reopening a closed tab restores its independent address-dropdown history alongside TabSettings. Keep only bounded lightweight snapshots (20 closed tabs, 20 addresses each), never retained native hosts; this does not imply restoring the disposed Shell Travel Log or persisting closed tabs across restarts.
- A Shell view-state capture must keep the same browser instance and read generation across GetCurrentView and all mode/sort/group/column getters. COM getters can pump navigation callbacks; reject an obsolete capture without replacing the last complete cache, and stop further native reads once invalidated. Synthetic getter reentrancy is not proof of physical Shell callback ordering.
- Protect the entire saved view until mode, columns, sorting and grouping restoration all succeed for the same browser/read generation. A missing view or failed field must block snapshots immediately, including inactive tabs before another capture; do not limit protection to custom columns. Retry on subsequent navigation, retain the saved values on failure, and stop writes/errors from a retired visit.
- Filter attachment must propagate missing IFolderFilterSite and SetFilter failures. A current failed quick-filter change restores the prior settings/filter/group and cancels retired group callbacks; keep selection suppression through rollback and never roll an old request over a newer visit/filter. Apply/clear UI entry points catch and show failures, retain the editor on failed clear, and do not record rejected patterns as successful history. Report rollback failure separately; uncreated tabs store preferences without trying a native refresh.
- Temporary ungrouping for filter enumeration must not become saved/duplicated "no group" state. Remember the confirmed key/direction before clearing, overlay only those fields on complete captures, and retain intent when a timer is cancelled or restoration fails. Clear it after current successful group/full-view restoration, browser disposal, or a complete capture confirms a different nonempty native group/direction; in the latter case retire the old timer/request instead of restoring over it. Reject retired group queues before replacing timers; recheck the visit after COM counts and before group writes/errors. Distinguishing explicit native "no group" from temporary ungrouping remains a separate visible acceptance case.
- Keep the app-owned Shell icon cache bounded (256 LRU entries, case-insensitive keys). Eviction drops cache references only; never dispose images still used by controls or trim native tab/history state. Reload on miss through the existing Shell path and preserve HICON cleanup. Cache-entry stress proves bounded references, not process MB savings or the cause of reported memory growth.
- Session/pin snapshots, tab duplication, cross-pane copies and closed-tab snapshots use the browser's confirmed CurrentPath. The pane's presentation path may lag while Navigated is queued; do not pair that older path with a newer view snapshot. Search still saves its real directory scope, never the transient search URI.
- TabState.Path is derived from Browser.CurrentPath, not independently assigned by queued notices. Current-directory commands, new-tab current-folder mode, address editing/tree/ancestors and search closing must use this confirmed location even before chrome repaint. Synthetic navigation notices must first update the test host location, matching production's commit-before-notify order.
- Reordering tab headers must preserve each hosted ExplorerBrowser instance and its navigation history. Keep displayed order, keyboard tab cycling, and saved tab order aligned.
- Cross-pane tab transfers rely on HwndHost parking/reparenting its existing native child. Do not suppress DestroyWindowCore with a transfer flag: WPF does not call BuildWindowCore again to clear it. Closing a transferred tab must still dispose its browser and destroy its HWND.
- After a window has saved its session and actually closed, explicitly dispose every file-view and tree host it still owns, including inactive tabs and popup/shared trees. WPF can park child HWNDs when the source window disappears; do not rely on Unloaded, garbage collection or process exit for cleanup. Stop pending saves and reject late save scheduling for the closed window; leave sibling windows' hosts alive.
- Workspace enumeration and QDR background IO must receive static state-only delegates, never capture a window or dialog in the worker. Closing cancels that window's UI waits and rejects late UI updates, without interrupting already confirmed writes or sibling windows. Observe late worker faults; cancellation of a wait does not prove disk IO stopped or process memory was reclaimed.
- Photo printing permits one image-loading batch per window. Keep the command disabled throughout loading, cancel decoding and its UI wait on close, and open the preview only if the owner remains visible and active. Cancellation between files does not guarantee a synchronous decoder can interrupt its current file immediately.
- The File > Restart application command restarts only the current process, saving each managed window session and preserving the window-session registry before relaunching the same executable after releasing its single-instance router. Other independent Explorer Dirs processes are not affected; if any session cannot be saved, leave the current process open.
- Keep visited ExplorerBrowser hosts attached to each pane's visual tree while switching tabs, and keep all four panes attached while switching layouts. Hide inactive views and panes rather than removing them; only remove and dispose a browser when its tab closes. Treat Shell travel-log preservation as pending real-window verification until the native handles are observed across switches.
- Pinned tabs stay before ordinary tabs within a pane. Duplicating a pinned tab copies its pinned state; accidental close actions and “close other tabs” preserve pinned tabs until explicitly unpinned. Save pin metadata in a separate `PinnedTabs.ini` beside the session INI so older releases do not erase it. Match saved pins only when their pane, tab position, and path still agree with the session.
- Layout switching stays in the top menu and toolbar; do not add layout choices to file-view or tab-header context menus.
- Keep Cut, Copy, Paste, Delete, Rename, Undo and Redo in the Edit menu and native shortcuts; do not duplicate these seven commands on the main toolbar.
- Adjustable dividers must retain the pane and native browser instances. Keep per-layout proportions in `LayoutProportions.ini` beside the session profile, with external-edit and newer-format protection. Persist explicit divider changes/reset only; window resizing must not replace the saved ratios with temporary minimum-size constraints. Dividers do not add Tab stops.
- Follow the user's 2026-10-20 order: complete menu, toolbar, navigation, file-view and status-bar functionality first, align component interaction second, and leave personalized themes and alternate button icon sets until last. File-operation correctness and inconsistent view colors remain defects to address earlier.
- Include Ctrl+mouse-wheel view changes in native Shell parity acceptance. Reuse Shell view interfaces, preserve per-tab settings and selection, and verify native message handling before adding a fallback that could process the same wheel event twice.
- Plan a global portable System/Light/Dark theme preference, defaulting to System. Keep the user's preference distinct from the currently resolved system color. Q-Dir import must not implicitly change the global theme; apply a consistent policy to new, imported and restored views. Native Shell content and WPF chrome require separate verification; a dark title bar does not establish dark file-view support.
- Compact density is a global top-menu preference saved in `UiPreferences.ini` beside the session profile. Keep normal spacing as the default, preserve the native Shell view and keyboard focus stops when density changes, and do not let older releases erase the preference.
- Route normal file-view keyboard shortcuts through the hosted Shell view. Keep file operations in Shell interfaces rather than duplicating copy/paste logic in WPF. If `IShellView.TranslateAccelerator` declines common clipboard/selection/undo/redo shortcuts, use the corresponding native Shell view command; never run file operations in WPF or let these routes intercept address/search/rename text editing.
- Keep Home/End/PageUp/PageDown and arrow keydowns inside their native content or rename editor. File-content fallback dispatches only after Shell S_FALSE and excludes column headers/editors; never duplicate S_OK, error, keyup or Alt system-key messages. Preserve original Ctrl/Shift key state and keep Tab/Enter/Escape on their existing paths.
- Clipboard/select-all/undo/redo fallback also requires exact Shell S_FALSE on WM_KEYDOWN. COM errors and unknown statuses do not authorize extra WM_COMMAND or a new file-operation focus restore. Bind unhandled input to its original browser/view/navigation visit and focused HWND across COM translation/release; consume retired input rather than forwarding it to a new target. S_OK operations may move focus normally and retain guarded restoration only for the same visit.
- Preserve the complete ICommDlgBrowser3 host contract and native live directory notifications. Verify pasted, deleted and externally created items update without F5; a successful disk operation alone does not establish a correct view. Supplement late local file-create updates with one coalesced `SHCNE_CREATE` on the ExplorerBrowser STA only when the actual Shell count trails the expected count; never synchronously flush one notification per file during a burst. Keep the count fallback, selection/focus checks, and 3,000-item responsiveness probe. In hidden refresh probes, wait for both count reconciliation and the asynchronous refresh callback before asserting restored selection/focus; Shell count convergence can precede restoration. If a probe changes selection through Shell COM instead of a real input path, call the product input-settling path and wait until its saved selection snapshot matches the actual Shell selection before testing preservation. Also verify a native live update that reaches the expected count without fallback does not silently discard unaffected selected items. Keep native COM slot and output-buffer checks when changing this site.
- Treat `SHCNE_CREATE` as a nonfolder file notification only; folder create/delete event types are `SHCNE_MKDIR`/`SHCNE_RMDIR`. For folder changes, verify the watcher event, final Shell view count, and whether the count fallback was needed. The product may send `SHCNE_RMDIR` only after coalescing deleted paths for 250 ms and confirming the latest exact stale Shell item has `SFGAO_FOLDER`; never infer type from the missing filesystem path. Skip ordinary files, long/relative paths, unavailable items or attributes; retain the count fallback in every case because RMDIR did not eliminate fallback in every product-host sample. Sending `SHCNE_DELETE` for a file did not improve stale-view timing. Keep the 10,000-item one-query-per-burst cost and Dispatcher responsiveness checks. Cross-volume `MoveItem` verification must separately confirm source `Deleted`, destination `Created`, both view counts, and file content; a single successful disk operation does not prove both panes converged.
- Menu/toolbar file commands use canonical Shell verbs and native enabled states, never translated captions. Query on explicit menu/toolbar interaction rather than periodically creating extension menus. Reacquire the command context on invocation and cancel if the pane, navigation or observed selection changes during preparation. A successful invocation is not evidence that a file operation completed.
- NewFolder availability may require initializing the canonical New submenu through IContextMenu2 before reading native item state. Keep parent and child disabled states, avoid initializing unrelated extension submenus, and revalidate the request after this potentially reentrant preparation. Preserve the shared New Folder observer/rename path for every entry point.
- Do not repair item focus before dispatching a file command if that repair can change selection. Restore focus after Shell accepts the command. Discard the whole command-state snapshot when navigation, selection or current-tab identity changes during menu queries.
- All/None/Invert selection operates on the native view's PIDLs, not a fresh filesystem enumeration. Snapshot before writing and cancel stale preparation. Preserve the focused item's actual selected bit during focus repair; neither unconditional SELECT nor bare FOCUSED preserves both selected and unselected items. Treat multi-batch inversion as nontransactional and stop remaining batches if the view changes.
- Capacity queries run off the UI thread, retain the current directory for mount-point semantics, and report caller-available capacity rather than ignoring quotas. Bound native calls across panes; cancelling a wait must not release a slot until the underlying call actually ends. Clear or reject results after navigation, tab switches, or hiding, and never substitute zero for unavailable capacity.
- Selected size uses the Shell selection's fast property store only. Label partial availability explicitly; distinguish missing properties from a valid zero-byte size. Do not recursively calculate folder sizes or open slow/offline content to fill missing properties. Reject snapshots when selection count/version or navigation changes during the read.
- Recursive directory-size totals run only after the user explicitly requests F9; never start them automatically during navigation, refresh, or tab/layout changes. Keep the scan cancellable and off the UI thread, and do not follow reparse-point directories.
- A navigation failure must settle read availability for the matching request as well as report an error. Do not let a late success/failure unlock a newer navigation. ExplorerBrowser callbacks identify locations rather than request tokens; keep repeated or unidentifiable targets conservative and verify native callback behavior separately from state-machine tests.
- Retiring a navigation callback does not authorize publishing its address, capacity or error. Publish only the settled current visit and version queued UI work across same-path revisits. Reconcile ambiguous batches against the actual Shell view location; if unavailable, preserve cached session state and report the failure. Deliver a reconciled failure after its location notification so status text does not erase the error.
- Location publication and input completion are distinct. Carry the originating application request number through queued directory/search/failure notices; an older native visit may update the actual tab location, but must not finish newer address/search input, clear its retry target or consume its focus intent. Partial repeated-target batches cannot acknowledge input; an already reported failure cannot later become input success. Invalidate prior preparation even when a new submission fails validation.
- New Folder continues to invoke the Shell background command. Do not synchronously enumerate every child directory to infer what it created. Automatic rename may use a short-lived observer on a fixed local drive only, and must require exactly one observed folder whose path matches the Shell-focused item; abandon rename when evidence is missing or ambiguous.
- Revalidate the original New Folder request after Shell menu preparation and before invocation. Cancel stale work after navigation, tab/pane changes, or a newer request. Delayed automatic rename must also retain the original navigation version, observer identity, selection and active file-view focus intent; an old timer callback must never cancel a newer operation's observer.
- Treat `IShellView.SelectItem(..., SVSI_EDIT)` success as Shell accepting the request, not proof the inline rename editor owns focus. Keep the operation pending until the native edit control is focused; after Shell accepts the request, do not issue it repeatedly while waiting.
- Keep navigation history independent for each tab by using ExplorerBrowser's travel log. Backspace and Alt+Up open the parent folder; Alt+Left/Right navigate history. Tab and Shift+Tab traverse each visible pane's navigation buttons, address, selected tab header, Details column header when present, and file items in exact reverse order; then wrap to the next/previous pane. Ctrl+Tab cycles tabs in the active pane; Ctrl+1 through Ctrl+9 select that pane's displayed tab positions, with out-of-range numbers doing nothing. Restore file-view focus after layout changes; preserve address-bar editing shortcuts.
- History button states come from each browser's native CommandStateChange connection point when available. Keep each direction unknown until notified, and preserve navigation attempts if subscription is unsupported. Cache notifications during pending navigation but gate actions until settled. Queue UI updates with subscription identity checks and refresh only the current tab. Disconnect callbacks before Unadvise; failed unsubscription must not stop remaining cleanup. Unused public browser events must preserve input/output parameters. Do not infer history from path equality or treat command-state notifications as navigation completion.
- Breadcrumb segments navigate the current tab only. Clicking empty space or separators in the modern address bar enters full-path editing; use bubbling mouse handling so path buttons retain navigation. Preserve Alt+D/Ctrl+L, the editable full path, and its existing single Tab focus stop; breadcrumb buttons must not create extra stops or take focus from another pane.
- Continuing to edit an address after submission revokes the old completion's permission to replace that draft. Preserve edited search text across late success/failure notifications and refocusing, even if the input no longer has keyboard focus; a matching result may acknowledge it. Explicit search close and tab switches keep their existing reset behavior. Unshown event tests do not establish native callback ordering or rapid repeated-submission correctness.
- Deferred focus after tab selection must recheck the owning window's current file-focus intent when the callback runs. A selected, visible tab alone does not authorize taking focus from another pane, the address editor, or the keyboard's tab-header stop.
- Directory/search completion must consume only its current navigation's pending focus request and use the existing guarded native restorer. Do not keep denied requests for another visit, interrupt a native rename/header target, or bypass current pane/window/foreground checks. Startup initially requests file focus; subsequent editor focus cancels it. Search submission transfers focus only while its source editor/button and active window still own the interaction; synchronous startup failure must not transfer it.
- The optional directory tree uses an independent native NamespaceTreeControl. Show/hide must not navigate or recreate file browsers. Keep its global visibility in NavigationTree.ini beside the session, default off; create the tree only when enabled. Store the Q-Dir-style “select from list and expand” preference in NavigationTreeSelection.ini, default on; a single selected Shell folder may update the corresponding visible pane tree or the shared tree for the active pane without navigating the file view or taking focus. Include the tree between tab header and file-view header in Tab/F6 order. Cancel directory synchronization on tab changes, hiding, disposal, and user input; validate the request after reentrant COM calls. Only confirmed native user-selection causes may navigate the current pane; delayed programmatic selection notifications are not user commands.
- File operations and Shell confirmation dialogs must return keyboard focus to the active tab's actual file-content HWND. Do not treat the outer Shell view HWND as the file list, and do not steal focus from an address box, toolbar control, another pane, or another application.
- After a Shell file operation, verify both the Win32 content focus and the Shell item focus. If Windows leaves no foreground window while this app is still active, reassert this app's foreground focus; never take foreground focus from another application. Keep existing multi-selection when restoring a focused item.
- Keep standard shortcuts local to the app and provide menu or toolbar routes for actions whose key combinations may be registered globally by other software. Do not install global keyboard hooks or register global hotkeys to compete with other applications.
- Refresh this process's user and machine environment when Windows announces an Environment settings change or the user invokes the manual command. Launch commands directly from the refreshed process so they inherit the new values without restarting the file manager; do not modify persistent registry values or promise inheritance for programs started through file associations.
- Validate the full environment refresh plan before mutating the process block. If a write fails, restore variables changed earlier in that refresh; report rollback failure explicitly instead of reporting a successful refresh.
- Current-directory search uses a Shell search location in the existing ExplorerBrowser. Keep each tab's saved path as a real directory; search queries remain runtime navigation state. F3/Ctrl+E/Ctrl+F focus the pane search box; Enter or the pane's Search button submits, and Escape returns to the directory. When the search bar is visible, Tab and Shift+Tab include its input, Search button, and close button before the tab header.
- Search navigation must resolve to an actual Shell folder before BrowseToIDList; a search-ms protocol item may launch another Explorer window. Preserve query/scope identity across Shell PIDL normalization and native travel-log callbacks. Default captions and ILIsEqual alone do not distinguish queries; keep browser-local issued identities, reject conflicting native names, and never infer a query from an arbitrary caption.
- A delayed Pending callback for an app-issued search must not cancel a newer directory probe. Keep request and browser-instance checks across search preparation and native ERROR_BUSY retries; bound retries, preserve PIDL lifetime until they finish, and never let old-instance cleanup retire a new browser's navigation. Verify rapid search-to-directory and search-to-search transitions against actual host state, published events and native results.
- Register app-issued folder navigation and its retry target using the confirmed PIDL's persisted identity, not the original address alias. Recheck the directory request after resolving that identity. Pending/failure callbacks must recognize virtual folders as well as filesystem paths, retire the same registration key, and preserve a newer request. Keep repeated-target counts; synthetic callback tests do not establish real Shell ordering.
- The executable may accept one directory argument for future folder-open routing. Resolve its syntax without probing the filesystem, preserve the restored session, and open the requested directory in a new first-pane tab. Reject unsupported arguments without changing the session. Do not change Windows associations or Win+E routing before the reversible system-entry work is verified.
- For same-profile folder forwarding, only the protocol's exact accepted and rejected reply bytes are definitive. Treat missing, malformed, or unknown replies as uncertain so the launcher never reports that a possibly handled directory was definitely rejected.

## Source, development, and releases

- `src/` contains source code and local build/debug output. Never tell the user to run an executable from `src/` as their daily-use release.
- Keep portable INI settings out of the registry. Published versions share `profile/ExplorerDirs.ini` beside the repository's `releases/` directory; debug builds use `src/.state/ExplorerDirs.ini`. A release copied elsewhere uses its own `profile/` next to the executable. Do not merge development and release profiles implicitly.
- Persist the active visible pane and each pane's selected tab by displayed order in the session INI. Older profiles without these fields select the first pane/tab without being treated as damaged; invalid selection metadata must not discard readable tabs.
- Give each application window an independent session INI. Keep `ExplorerDirs.ini` as the backward-compatible primary session, register additional generated window sessions in `WindowSessions.ini`, and restore the ordered roster at startup. When one of several windows closes, remove only that session; preserve the final session for restart recovery. Keep favorites and application-wide preferences at profile scope, and save pinned-tab metadata beside its owning window session.
- Remember each window's normal position/size and maximized state by default in `<session-stem>.WindowPlacement.ini`. Use paired native GetWindowPlacement/SetWindowPlacement workspace coordinates, preserving negative monitor coordinates; never mix them with WPF DIP coordinates. Save during periodic session capture, close and restart. Minimized/full-screen geometry must not overwrite ordinary restoration state; saved placements take priority over startup cascading. Copy primary and registered-window placement sidecars into isolated previews.
- When activating an existing minimized window, preserve its last nonminimized maximized state in both no-argument and folder-forwarding routes. Immersive F11 restores as a normal borderless window without clearing its separate exit state; activating an already expanded window must not change its presentation.
- Cascade new sibling/workspace windows and unplaced restored windows within the source window's monitor work area, never the primary-only SystemParameters.WorkArea. Use native screen coordinates for GetWindowRect/SetWindowPos, retain saved-placement priority, and do not activate the source while positioning its new window. Mixed-DPI WPF rendering remains a visible acceptance item.
- Enforce one process owner per profile. A second no-argument launch should activate the existing window; if route ownership cannot be obtained and forwarding is unconfirmed, stop before opening registered sessions so separate processes cannot write the same files.
- Session saves must not overwrite changes made by another instance or an external editor after load. Coordinate current-version writers for the same profile path and leave the on-disk file untouched on conflict.
- Store favorites in a separate `Favorites.ini` beside the session INI so older releases cannot remove them while saving sessions. Preserve external edits, invalid files, and newer formats before writing; coordinate current-version writers for this file as for the session INI.
- Store Program Starter commands in an independent profile `ProgramStarter.ini`; keep them separate from `.lnk` favorites. Q-Dir `[Program]` import must show a review preview before explicit application and must never modify the source Q-Dir INI or execute imported commands automatically. Preserve external edits, invalid files, and newer formats before writing.
- Whole-workspace favorites are `.qdr` snapshots in `Workspaces/` beside the current profile. Reuse export validation and import preview/backup/append behavior; do not silently replace open tabs. List only top-level file names off the UI thread, bound the menu count, and read the clicked file afresh. Saving outside this directory is an export, not an automatically indexed favorite.
- Record one per-instance run marker under `crash-logs/`, remove it on clean exit, and archive only markers whose process identity is known to have ended. Preserve an existing abrupt report on filename collision by archiving the newly ended marker under a unique name; do not leave it to trigger repeated warnings. A stale marker means an unclean exit or failed cleanup, not proof of a Shell extension crash. Keep run reports free of browsing paths, environment values, and file names.
- Treat WER local dumps as optional system diagnostics, not portable app settings. Never enable them automatically. Only configure a named application's per-app WER key after explicit diagnostic opt-in; preserve existing or externally edited keys, leave collected dumps for manual review, and keep dump files out of Git.
- Persist global layout/default new-tab view and each tab's path, view mode, icon size, sort columns, and grouping independently. The default view stores both mode and icon size and offers the same eight presets as the current-view menu; changing it affects new tabs only. Preserve unmatched legacy/custom defaults without coercing them to a preset. Duplicating a tab copies its live settings; a new tab uses the configured default view, initially Details. Preserve legacy JSON during one-way migration.
- Persist each tab's visible columns by ordered Shell property keys and widths through IColumnManager. Copy this snapshot when duplicating; leave new-tab columns to Shell defaults. Do not persist translated column captions. Session format v7 adds per-tab native preview-pane visibility to v6's quick-filter settings; v5 added strip layout IDs 9–12, v4 added independent quad row ratios, and v3 added the new-tab default icon size. Preserve a loaded v1–v6 snapshot in a unique `.before-v7-*.bak` before upgrading; older readers must refuse to overwrite newer formats. New tabs start with the preview pane hidden; duplicate/reopen/import preserve the per-tab state. Layout proportions v4 backs up v1/v2/v3 before saving, retains old shared two-axis fractions, stores three/four positive finite weights for strip layouts, and permits a separate `BottomHorizontal` only for quad layout 4. Older quads inherit their single saved `Horizontal` value for both rows. Four-pane geometry must keep native pane objects in one parent; resizing must not overwrite saved ratios with minimum-clamped dimensions. Incomplete column reads must not replace a complete snapshot; failed restoration must not be saved back as though it succeeded.
- Periodic session saves read live Shell view settings only for currently visible tabs. Capture a tab before it is hidden by tab or layout switching, and save cached settings for hidden tabs. Treat unavailable live views, failed or incomplete Shell getter results, and invalid sort-column counts as capture failures after navigation. Keep the last complete cache, do not overwrite the existing session INI until that tab can be captured again, and do not duplicate a tab from a failed capture.
- Put each usable build in a new immutable `releases/<version>/` directory using `scripts/publish.ps1`. Use a unique staging directory and fail the final rename if the version directory already exists or appears during publication; leave failed staging files for inspection. Never publish over a running release or make a release depend on files under `src/`.
- Keep generated release binaries out of Git. Track release instructions and build scripts. Verify the exact release executable launches before calling it usable.
- When the user explicitly requests an early temporary preview, it may be packaged before full GUI acceptance, clearly labeled unverified. Use `publish.ps1 -IsolatedProfile` to place its executable under the version's `app/` directory with a separate profile copy; never upgrade the daily-use profile during temporary preview. Include changes and known issues, and retain the normal release acceptance gate.
- Keep isolated-preview profile copying aligned with the current independent settings stores, including `NavigationTreeSelection.ini`, registered `WindowSessions.ini` sessions and their pinned-tab sidecars, and top-level `Workspaces/*.qdr` favorites. Copy bytes without importing, executing, or modifying source settings; copy only generated window session names listed by the registry and do not recursively include unrelated profile content. Packaging-only fixture tests do not establish a usable app build or GUI acceptance.
- Do not change Win+E, folder associations, or registry routing until there is a tested, reversible enable/disable flow.
- The optional folder/drive context-menu verb must stay nondefault and per-user. Never point it at `src/` or an older release lacking `FolderRoutingCapability.ini`; require the exact release hash and GUI verification before enabling it. Disable only keys still matching this project's ownership marker and command.
- Run `pwsh -NoProfile -File scripts/folder-verb-smoke.ps1` to verify folder-verb install, idempotence, conflict refusal, external-edit preservation, and removal under unique temporary `HKCU\Software\ExplorerDirs.Tests\<GUID>` keys. The smoke must never exercise the default `Software\Classes` registration or launch the fixture executable.
- Folder routing may wait for a receiving window to finish startup, but disposing the router must cancel that wait and release its per-profile ownership lock. A client timeout is uncertain, not proof that the folder was rejected; do not acknowledge before a tab is actually accepted.

## Maintaining the project

- Keep `docs/shell-parity.md` current when changing core browsing behavior. Compare Q-Dir's multi-pane workflow and Windows Explorer's native Shell interaction; prioritize file-operation/focus correctness, menus, navigation, view settings, then tree/preview integration.
