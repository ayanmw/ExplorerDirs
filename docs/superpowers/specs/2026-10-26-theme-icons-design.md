# Explorer Dirs 主题与图标设计

状态：待用户审阅；本文件记录设计方案，不授权开始实现主题或图标代码。

## 意图

让 Explorer Dirs 在 Windows 明暗主题变化时保持一致、易读，并让应用自身的图标在浅色、深色和高对比度模式下清楚可辨。Q-Dir 的多窗格密度和文件颜色提示是参考；最终体验优先遵循 Windows 用户对资源管理器控件和 Shell 项目的预期。

## 目标

- 默认跟随 Windows 的应用明暗偏好和系统强调色，并能在系统设置变化时即时更新。
- 保留用户显式选择浅色、深色或自定义强调色的能力；设置保存在程序旁的便携 INI。
- 让菜单、工具栏、标签、状态栏、地址/导航控件和应用对话框共用语义颜色角色。
- 保持原生 Shell 文件/文件夹图标；应用自有命令图标采用同一套可主题化资源。
- 继续验证文件区的深色表面与 Q-Dir 式逐项颜色规则，同时保护 Shell 选择、焦点、排序、分组、菜单、拖放和文件操作。
- 对 Q-Dir 可确认的主题或颜色规则提供明确导入；对无法解析的值在预览中说明，避免静默误应用。

## 非目标

- 不复制 Q-Dir 二进制、图标、主题资源或私有实现。
- 不把 `.qdr` 布局状态误当作完整主题文件，也不根据未确认的字段值推断颜色。
- 不用 WPF `ListView` 替换原生 Shell 文件视图。
- 不以标题栏变色或 WPF 控件变色宣称原生文件区已支持深色主题。
- 不在本设计阶段迁移产品文件视图到新的 Shell 宿主。

## 方案比较

1. **只做应用外壳的 Windows 跟随主题。** 复用当前 WPF 颜色资源和 `Theme.ini`；实现成本较低、风险小，但文件区不能与外壳同步变色，逐项高亮也无法覆盖。
2. **统一设计系统，并分开实现 Shell 文件区。** WPF 使用语义颜色角色和系统主题监视；Shell 图标保持原生；文件区暗色与逐项规则在隔离 `IShellView` 原型中逐门槛验证，通过 Explorer 操作、刷新和可见验收后再决定产品接入。Q-Dir 导入按“整窗主题”和“逐项颜色规则”分开处理。该方案覆盖用户目标，同时能把 Shell 兼容风险限制在已验证边界内，推荐采用。
3. **整体改用自绘文件列表及应用图标。** 最容易完整控制外观，但会重新实现 Shell 选择、列、排序、分组、菜单、拖放、属性、虚拟位置和文件操作，与“复用资源管理器操作方式”直接冲突，排除。

推荐方案 2。产品仍以当前 ExplorerBrowser 文件视图为行为基线；隔离原型只是研究和验证工具，不能自动获得迁移资格。

## 已核实现状

- `ThemePreferenceStore` 已在 profile 目录读写 `Theme.ini`，支持 `System / Light / Dark` 和可选自定义强调色，并保护未知格式和外部修改。
- `SystemThemeMonitor` 通过 Windows `UISettings` 获取系统明暗与强调色变化；`ApplicationThemeController` 将其映射到 WPF 颜色资源，并在高对比度下撤销自定义颜色资源。
- `ThemePalette` 已提供窗口、控件、边框、弱化文本、强调色和选中态等颜色角色；仍需检查所有菜单、工具栏、状态栏、标签及对话框是否完整消费这些角色。
- Shell ExplorerBrowser 文件区的颜色由 Windows 原生视图管理，WPF 资源不能直接控制它。
- `NativeProbe` 隔离 `IShellView` 已在 Private Desktop 的五种标准同步视图中取得逐项绘色和像素证据；尚未证明产品 ExplorerBrowser 的 DirectUI、Content/其他模式、实际用户桌面和完整 Q-Dir 交互。
- 项目读取的 Q-Dir `.qdr` 样本只观察到 `colorthema=0`，没有确认可导入的颜色规则正向样本。项目只读调查记录了 Q-Dir `Q-Dir.ini` `[Filter2]` 规则和公开通配符语义，但数值列语义及 `.qdr` 序列化方式尚未完整确认。
- Q-Dir 官方功能页列出多种预设主题及文件颜色/高亮功能；官方 FAQ 说明颜色过滤和背景选项，并指出树视图背景不能按该方式着色。这些能力不可简单等同于一个 Windows 强调色。

## 设计

### 1. 主题状态和调色板

- 继续使用 profile 级 `Theme.ini` 作为唯一全局主题源，不按窗格或标签分别保存窗口颜色。
- `Mode` 继续采用 `System / Light / Dark`。系统模式分别读取 Windows 应用主题与强调色；显式浅色/深色仍可选择跟随系统强调色或自定义颜色。
- 把调色板作为语义角色维护：窗口表面、次级表面、主要/弱化文本、边框、强调、强调文字、选中背景/文字、悬停和禁用态。控件不直接硬编码具体 RGB。
- 系统强调色只作为强调来源，不把所有背景直接染成强调色。选中态保持对比度门槛；高对比度优先交给 Windows。
- 系统变化在当前进程立即生效，并写明动态刷新不应更改用户的显式模式选择。

### 2. 图标

- 文件、文件夹、驱动器和 Shell 虚拟位置的项目图标继续由 Windows Shell 提供，保留系统覆盖图标和扩展关联。
- 应用自有图标采用集中资源字典，优先用可缩放的矢量几何路径；颜色引用语义角色，尺寸、描边宽度和命中区按工具栏/菜单/标签场景统一。
- 初期不提供多个图标包或用户自定义图标入口。先统一布局、导航、刷新、标签和文件视图模式图标，再做浅色/深色下的对比检查。
- 若某个命令采用 Shell 自带图标或系统 glyph，需保持系统来源，不把其二次绘制成不一致的风格。

### 3. 原生文件区与颜色规则

- 第一步只完善 WPF 壳层主题，不把文件区变黑或改变 Shell 选择样式。
- 文件区方案必须保留 Explorer 的右键菜单/动词、常用快捷键、重命名编辑焦点、原生排序分组、列头、拖放、文件操作、实时变化、每标签视图状态和四窗格标签生命周期。
- 隔离 `IShellView` 的产品迁移仍受 `docs/superpowers/specs/2026-10-25-ishellview-host-migration-gates.md` 的阶段门槛约束。颜色工作不得绕过该设计或先切换产品窗格。
- Q-Dir 逐项颜色规则作为独立于全局主题的可选数据；目录/隐藏/只读标记与普通文件扩展规则分别建模，具体匹配和优先级只按官方已确认语义及正向样本实现。树背景不承诺逐项规则着色。

### 4. Q-Dir 导入策略

- `.qdr` 布局导入不改变全局 `Theme.ini`，也不自动启用 Q-Dir 颜色方案。
- 只有在 `.qdr` 中找到并由官方资料或多组对照样本确认编码后，才导入已知的 Q-Dir 主题/背景/颜色规则字段。
- 若将来支持从用户选定的 `Q-Dir.ini` 导入颜色规则，先显示规则名称、匹配条件、颜色和启用状态；用户确认后写入本程序自己的便携配置，不修改源文件。
- 无法确认的预设编号或字段只在导入预览列出“未导入及原因”，不得猜测映射到 Light/Dark/System。

## 分阶段实施与验收

1. **应用主题覆盖检查**：枚举 WPF 菜单、工具栏、标签、导航、状态栏和对话框，完成语义资源接线；验证旧 `Theme.ini` 迁移、系统模式、自定义强调色、高对比度和多个窗口共享设置。
2. **自有图标统一**：统一现有应用图标资源并覆盖浅/深色背景；验证布局按钮的命中区域、提示文本及键盘焦点顺序不变。Shell 项目图标保持原生。
3. **文件区原型门槛**：继续隔离验证 Shell 视图模式、排序/分组、列、选择/焦点/悬停、右键菜单、键盘、文件操作、拖放、刷新及重启视图状态；任一核心行为退化即不进入产品接入。
4. **可见主题验收**：在系统浅色/深色切换、高对比度、不同强调色、四窗格和多标签下检查 WPF 绘制及文件区；真实桌面验收与隐藏测试分别记录。
5. **Q-Dir 颜色兼容**：收集启用颜色保存的 `.qdr` 正样本和对照配置，先确认字段语义，之后再设计可回归的导入范围。

每个阶段作为独立批次提交 Git；没有可见 Shell 证据时，只报告源码、构建、smoke 或隐藏宿主达到的层级，不宣称完整主题或 Q-Dir 兼容。
