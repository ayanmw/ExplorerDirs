# temp.86 目录空间分析实现

工具菜单增加“分析当前目录空间…”，打开用户显式触发的独立窗口。选项中的文件夹大小来源存入 FolderSize.ini；分析窗口默认使用此来源，也可为本次分析另选来源。此实现仍在 src，未发布。

## 行为与生命周期

- 后台枚举当前层直接文件和目录；文件读取逻辑长度，目录交由 FolderSizeDataSource 的 Auto/Everything/BuiltIn 路由。链接不递归遍历，缺值和不可读结果保留可见状态，不能记为完整的零。
- 列表按大小初始排序，大小/百分比列使用数值排序；显示名称、逻辑大小、占已知总量的比例、来源和部分结果说明。
- 二分矩形树图按权重面积分配，使用本项目实现，没有引入 GPL 应用源码或额外 UI 框架。前 150 个非零项单独绘制，其余合并为“其他项目”；列表保留所有枚举项。
- 单击图块联动列表；双击目录或图块下钻；可上移、输入路径、取消、在文件视图新标签定位选中项。选择变化只更新已有图块边界，不重建图块，避免闪烁及破坏双击命中。
- 仅保留当前完成层级快照；重新分析取消旧任务，以请求版本拒绝过期结果。取消或失败保留上一份完成结果并恢复其路径。关闭清空列表、图块与快照，并取消任务。
- 进度通过计数器合并，UI 每 200 ms 更新，避免 Everything 成批结果为每目录排队 Dispatcher 回调。

## 2026-11-04 缩放时限制快照读取范围

继续审查发现，上一轮虽然只分配 150 个条目引用，DrawMap 每次尺寸变化仍遍历整份快照来汇总隐藏部分。现将绘图输入准备收敛为 SpaceAnalysisSnapshot.CreateMapItems：利用 ReadAsync 已保存的大小降序和 KnownBytes，最多读取前 150 个正大小条目，以完整合计减去它们得到“其他项目”。完整快照、列表、条目引用、已知/未知语义和面积权重保持不变；没有新增第二份完整明细或缓存。

旧循环原样移入数据方法后，计数夹具在读取第 151 项时复现失败；改为复用合计后通过。验证 149、150、151 和逻辑 1,000,000 条目：访问次数严格为 min(N,150)，独立图块最多 150，余项合计准确，全部权重之和不变；零值/未知项不产生正面积图块。逻辑百万项是按需生成的计数夹具，不是实际分配百万条目的内存或 UI 帧率测试。真实目录 13 B 文件＋7 B 子目录的快照，绘图引用与合计保持一致。
