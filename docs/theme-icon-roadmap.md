# 主题与图标路线图

## 目标

让 Explorer Dirs 在浅色、深色和高对比度 Windows 环境中保持一致、可读的界面，同时保留 Shell 文件视图的原生交互。系统主题、强调色、Q-Dir 文件颜色规则和应用图标是不同层次，分开配置和验证，避免一种颜色设置意外改变另一层。

## 已有基础

- profile 级 `Theme.ini` 保存 `System`、`Light`、`Dark` 和 Windows/自定义强调色，缺省为跟随系统；v1 主题配置仍可读。
- `SystemThemeMonitor` 读取 Windows 当前明暗偏好和强调色，并监听颜色变化；`ApplicationThemeController` 将语义色应用到主窗口、菜单、工具栏、导航、标签、输入控件、选择控件、列表与辅助打印窗。
- 高对比度时移除应用自定义系统色并恢复 DWM 窗口框默认色，交还给 Windows。
- 活动窗格、选中项、标签提示和应用命令/查看方式图标使用强调色语义资源；应用图标已改为共享矢量几何。
- 文件窗格继续使用 ExplorerBrowser。WPF 资源不会自动改变 Shell 子窗口的绘制。
- 隔离 `IShellView` 原型验证了部分 Q-Dir 逐项颜色规则与像素绘制，但没有接入产品 ExplorerBrowser，也没有证明切换产品视图宿主后可保持现有导航、焦点、拖放和文件操作体验。

## 方案与取舍

1. **把整套界面完全自绘，包括文件列表。** 可控度高，但会复制大量 Shell 的视图、菜单、键盘、无障碍和文件操作行为；当前项目目标是复用 Windows Shell，因此不作为默认路线。
2. **仅跟随 Windows 的明暗模式，不提供自己的强调色或 Q-Dir 颜色兼容。** 风险低，但无法满足用户要求的主题颜色联动，也留下已知的 Q-Dir 颜色能力差距。
3. **分层主题（推荐）：** WPF 应用界面使用语义色板，默认跟随 Windows 明暗模式和强调色；原生文件视图保留 Shell 行为，先独立验证其主题/着色能力，再决定产品接线；Q-Dir 文件颜色规则独立于整套主题处理。这样能够逐步实现用户可见能力，同时不把 WPF 深色资源误认为原生文件区已经支持深色。

推荐第三种。产品主题设置使用便携 profile 配置；导入 `.qdr` 不隐式改全局主题。Q-Dir 收藏中确实存在并已由样本/公开格式确认的颜色设置才参与导入预览；无法映射的值明确提示，不猜测。

## 实施阶段

WPF 语义色资源阶段的实施步骤见[实施计划](superpowers/plans/2026-10-27-theme-semantic-resources.md)。该计划只覆盖应用自有 WPF 外壳；ExplorerBrowser 文件区和 Shell 文件图标仍按下文独立调查与验收。

### 阶段 1：完成应用界面语义色

- 保留 `System / Light / Dark`，默认 `System`。`System` 同时读取 Windows 明暗偏好和系统强调色；显式 `Light` 或 `Dark` 固定明暗，但仍可跟随系统强调色。
- 以颜色角色而不是零散硬编码覆盖窗口、菜单、工具栏、地址栏、标签、状态栏、边框、选中态、焦点环和禁用态。
- 处理 Windows 颜色变化通知、多窗口更新、设置文件格式保护和应用重启恢复。
- 高对比度开启时保留 Windows 控制权；颜色对比度计算保证文本和图标在强调色背景上可辨。

### 阶段 2：验证原生文件视图主题边界并修复已知不一致

- 将“只文件列表区域变黑”的现象作为单独问题复现和定位；分别检查 ExplorerBrowser、Shell 子窗口和 WPF 宿主的背景、选区、列头及滚动条。
- 覆盖八种 Shell 查看方式、焦点/选择、排序/分组、标签切换、布局切换、DPI 与高对比度。
- 优先保留 ExplorerBrowser。若逐项颜色或完整深色外观需要改用隔离 `IShellView` 原型，必须先验证产品级导航、Shell 菜单、拖放、键盘加速、焦点、异步更新和生命周期，再决定是否接入；探针结果本身不算产品验收。

### 阶段 3：强化色策略与主题预设

- 默认“跟随 Windows 强调色”；另提供用户自定义强调色，并在 `Theme.ini` 中保存来源与颜色值。
- 强调色只用于活动窗格、选中/焦点提示和少量主要动作，避免把大面积背景染成系统强调色。
- 提供应用内浅色/深色预设，并确认预设只覆盖应用可控的语义色，不覆盖用户逐项颜色规则。

### 阶段 4：Q-Dir 主题和颜色规则兼容

- 将 Q-Dir 颜色能力拆成独立范围：文件视图背景（`#BG`）、活动视图背景（`#BG-A`）、文件/文件夹逐项规则（如 `#DIR`、`#RO`）、活动地址栏高亮，以及目录树的颜色筛选。Q-Dir 官方说明目录树不能设置背景色，因此不把地址栏、文件视图和目录树强行当成同一套全局换肤。
- FAQ 117 示例列出 `useColor`、`useTreeColor` 等开关，FAQ 47 说明颜色/背景设置可保存到收藏。当前本机可读 `Q-Dir.ini` 的 `[Filter2]` 有 12 条有效规则，覆盖 `#Hidden`、扩展名、`#DIR`、`#BG` 和 `#BG-A`，提供了真实规则样本；但它不是保存颜色规则的 `.qdr` 正向样本，且公开资料未完整定义每条规则数值列的字段顺序/语义。可以据该 INI 样本继续核对解析，不得把未确认列映射为产品颜色，也不得根据字段名猜测。
- 导入器列出可识别设置、无法映射项目和将要应用的范围；用户确认后只修改本程序配置，不写入 Q-Dir 配置。
- 文件规则按 Q-Dir 优先级/逐属性语义处理。若产品视图无法可靠呈色，设置项应显示不支持或受限状态，不静默伪装成已生效。
- 本程序导出的 Q-Dir 文件只写已经验证的基础字段；应用私有主题设置写在独立扩展字段中，并在不兼容时可忽略。

### 阶段 5：统一应用图标

- 保留文件、文件夹和 Shell 命名空间图标由 Windows 提供；只统一本程序菜单、工具栏、布局、标签和视图按钮。
- 建立统一的尺寸、对齐、笔画、填充和状态规则；优先使用可按语义色着色的矢量资源，避免把固定彩色像素图直接用于深浅主题。
- 先覆盖布局和查看方式等高频入口，再覆盖低频命令；活动、悬停、按下、禁用、高对比度与高 DPI 都有可读反馈。
- 不复制 Q-Dir 的专有图标文件；以用户提供截图为布局/辨识度参考，设计本项目自己的符号。

## 验收门槛

- **应用界面：** Windows 明暗/强调色切换时即时更新；显式浅/深模式行为明确；跨重启和多窗口一致；高对比度可读。
- **文件区：** 每种视图、活动/非活动窗格和选中项的颜色一致；排序、分组、菜单、键盘、拖放及导航不回归；Shell 项目图标仍正确。
- **Q-Dir：** 有真实 `.qdr` 样本证明字段解析与导出互操作；导入预览、取消无副作用、确认后读回正确。应用自身往返不能代替 Q-Dir 实际读取验证。
- **图标：** 所有主要界面入口在浅色、深色、高对比度及缩放环境下仍可辨识；文件与文件夹 Shell 图标不被应用主题替换。
- 单元/策略 smoke、编译、隐藏原生探针和可见桌面验收分别报告，不互相替代。
