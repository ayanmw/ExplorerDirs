# 导航回调与界面状态发布

2026-10-20。源码修复已构建和回归，真实快速导航/失败场景的 GUI 验收仍未完成。

## 修复的问题

此前 `ShellViewReadiness` 会阻止旧回调解除新导航的 pending，但宿主在调用它之后
仍无条件将成功回调路径写入地址状态和容量目录；失败回调也可能发送旧错误。
此外，排队的视图恢复只比较路径，快速离开再回到同一路径时可能执行前次访问的动作。
这是源码可确认的保护缺口；本机隐藏探测没有复现重叠的旧回调顺序。

## 当前规则

- `Complete` / `Fail` 明确返回该回调是否结束了当前批次。所有回调仍清理
  issued-path 计数；旧目标、无匹配请求、尚未结清的重复目标不发布位置或错误。
- `Generation` 继续保护同步读取快照；另设 `NavigationVersion`，
  只在新导航开始或宿主 Reset 时增加，用于排队的视图恢复、焦点与位置/错误通知。
  旧请求收尾不会废弃当前访问的有效排队动作，同路径重访也不会复活前次动作。
- 相同目标多次 pending 或无法识别 identity 的批次没有请求 token，
  最后一条回调不能单独证明最终位置。批次结束后通过
  `IExplorerBrowser.GetCurrentView → IFolderView.GetFolder(IPersistFolder2) → GetCurFolder`
  读取原生实际位置，再发布地址及容量。失败批次保留重试目标。
- 当前目录无法核对时，容量保持未知，界面收到明确失败通知；
  `_locationUnconfirmed` 使会话捕获保留原缓存并标记失败，不将未确认视图写入旧路径。
  下一次成功发布受支持的目录或搜索位置后解除此保护。
- 失败批次的错误通知排在同批次位置通知之后，以相同 Dispatcher 优先级执行，
  避免正常位置文字覆盖错误；两者执行时都再检查版本。

## 验证边界

控制台回归覆盖：旧成功/失败、不同目标交错、重复目标混合成功/失败、
未知身份、同路径重访、Reset 后迟到回调、旧请求收尾与当前排队版本。
重复/未知批次必须要求实际位置读取，不能按最后回调猜测。

隐藏 `--navigation-cancel` 复测收到真实 OnNavigationFailed，原目录保留，
后续导航与后退成功。每次实际 PIDL 核验同时调用生产 `ShellCurrentLocation`
读取器，与探测原有独立读取链及预期目录比较，均一致。
这验证读取器在本机测试目录及取消恢复路径可用，不证明所有虚拟目录提供方支持它，
也没有将合成重复批次冒充原生重叠请求复现。
