# 四次有界删除重验实验结论

日期：2026-11-05。结论：**不采用，实验结束；正常产品接线已撤回。**

## 范围与验收标准

复验暂停时未提交的三个文件：ExplorerBrowserHost.cs、ShellDeletedItemNotification.cs、ShellDeleteNotificationBatchSmoke.cs。方案为原始视图PIDL异步分片扫描（每32行或8ms让出Dispatcher），发送删除通知，等待350ms，按视图总数判断是否退出，最多4轮。目标是处理超过512行的批量删除，不以全视图自动刷新替代。

采用标准：默认软刷新下四窗格大目录的目录/单文件/三文件突发删除可靠；不破坏小目录同名重建及重命名；不会误移除已重建路径；退休/导航保护有效；不引入明显空列表和长时占用。未达到标准即不进入产品。

## 源码审查发现

1. 总数一致仅为数量合同：一个旧条目残留同时漏掉另一个新条目也可能总数正确，不能证明指定删除路径消失。
2. 原型按删除路径匹配后直接发通知，未在发送前确认路径是否已被重建。重试扩展了旧删除任务存活窗口，存在把新同名条目从视图误移除的风险；本次未通过独立并发重建夹具证明该风险实际发生，不将风险写成已复现故障，更不声称会删除磁盘文件。
3. 每32行/8ms让出仅限制连续处理窗口，不限制单次COM调用耗时或四轮累计成本。当前反例仍存在空列表；不能以异步关键字当成不卡顿证明。
4. isCurrent在让出后及发送前检查，finally释放COM/PIDL，源码已有退休保护；本轮没有额外导航/关闭故障注入，不能称完整生命周期已验收。因方案已拒绝，不继续扩大其实现。
