## 近期顺序

1. 交付 temp.75 供用户预览，先收集工具栏、位置恢复、标签及地址栏反馈。发布和开发 profile 隔离，保持每批 Git 提交。
2. 用户允许桌面并确认交接后，按隔离清单完成 P0：四窗格文件操作/方向键、F2、正反 Tab、背景菜单，再检查导航、视图状态和多屏。失败先复现/修复，不以便利功能盖过核心失败。
3. 固定相同目录/标签/操作批次，记录同一 PID 的 Private Bytes、Working Set、句柄、线程与托管堆；按阶段差分区分缓存、宿主泄漏、Shell 扩展及运行时，保留可复现样本再优化。
4. QDR 实际互操作、筛选分组/无分组、导出关闭、照片加载等补齐可见验收；据反馈调整路线图，决定下一次预览范围。

未获得桌面授权时继续源码、无窗口对象/COM/文件测试；不启动隐藏 Shell view 代替授权，也不把这类检查解释为 GUI 通过。

## 中远期

- 先完成隔离 IShellView 迁移门槛：真实 OLE 拖放/源端、菜单模态循环、导航历史、文件操作/通知、焦点、状态持久化、WPF 宿主与关闭。原型已有颜色像素和部分原生会话证据，但后续生命周期修复尚需原生复验。达标并评审后才考虑产品迁移；当前 ExplorerBrowser 继续承担产品功能。
- 以该评审结果决定逐项颜色与派生文件夹大小列的实现路径；保持原生操作体验。全面主题个性化和 Q-Dir 配色导入放在功能/组件稳定之后，不以视觉先行掩盖交互差距。
- 根据公开资料与普通产品观察确认标签组、预览格式过滤等未决语义，再规划模型和兼容迁移，不从翻译字符串推断完整功能。
- 确认基础稳定、兼容与内存后，再推进可撤销的文件夹打开/Win+E 接管。范围始终是替代文件浏览窗口，不替换桌面、任务栏或系统 explorer.exe。
- Win32/C++ 重写作为独立架构选项，只在固定负载 A/B 证明明显收益、并评估维护与 Shell 功能保留成本后再决定；目前不把全面重写当成内存问题的既定结论。
