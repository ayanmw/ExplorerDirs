# 通知事件队列协调实验

## 真实事件到原生视图

调度访问退休补证（2026-11-06）：将有限批次/延后确认提取为 NativeProbe 内的 `ProjectedChangeDispatch.Advance`，原生Watcher实验复用同一代码。每个外部派发、确认读取与ack后重新核对访问，嵌套Advance不重复派发；过期或异常时清空待办并失效事件队列，不重试可能已确认的半批ticket。`--projected-dispatch-smoke` 先缺实现红灯，正常实现通过；异常派发清理用例另有红灯，补异常失效后通过。覆盖批次上限8、延后确认、回调重入、派发前/派发中/读取中/ack中退休及异常清理，已加入后台脚本。

原生复用回归 `src/.state/projected-dispatch-native.log` 退出0，11阶段枚举恒1，108事件、32项增删、8KB更新、选区/清理及隔离守卫通过；单轮新增3487ms、删除1981ms。最后异常清理增补仅重验无窗口合同及Release构建。仍未接入App Dispatcher/目录监控，也未证明产品自动导航时机、多视图或并发对象替换通过。

批次确认补证（2026-11-06）：实验驱动改为有限在途队列，在后续消息循环轮次检查整批是否到达，再退休结构事件 ticket；单个 dispatch 内不再嵌套等待或泵消息。4 条、8 条上限对照均通过“不增加枚举”及前台/输入守卫。8 条候选的确认查询复用 OwnedAppListText.Find，只查询待办名称，不在每次确认读取 1029 行文字；最终 `src/.state/projected-watcher-view-batch8-targeted.log` 退出0，新增约3505ms、删除1876ms，108条事件全部处理且记录归零、销毁清理通过。相对上一轮串行新增5187ms/删除3674ms有所改善，但单轮耗时不是稳定基准或产品性能结论；4条与8条无单调速度关系，8不是已证明的最优/跨环境安全阈值。

目前仍由隔离探针外层消息循环轮询，无 App Dispatcher 定时/取消接线；并发同名替换、连续改名重协调、背压和多视图门槛不变。保留32项完整行集、精确大小、选区和枚举计数验收，目标查询只优化确认步骤，未降低最终断言。Changed事件在此阶段以通知成功作为完成，最终8KB断言另行确认；不能据此声称每个属性更新已逐项确认。

2026-11-06，`ProjectedWatcherViewProbe` 将实际 FileSystemWatcher 事件经队列派发到原生通知桥，在物理订阅暂停的 1029 行原生视图验证文件/目录增删改名、精确 8KB 更新、确认删除后的同名重建及 32 文件突发新增/删除，保留原选区和焦点，最终 metadata facts 回到 1027。

保留失败对照：`src/.state/projected-watcher-view-burst-diagnostic.log` 中行内容和 facts 正确，但 EnumObjects 为 1→2。分阶段日志 `projected-watcher-view-stages.log` 将首次额外枚举定位到 32 文件创建阶段；插入 DoEvents 的对照 `projected-watcher-view-yield.log` 仍失败。不能据此确定 Shell 内部的具体合并规则。

逐项确认新增行到达后再继续派发的候选，最终 `src/.state/projected-watcher-view-confirmed-bounded.log` 退出 0：11 个阶段的枚举计数均为 1，原有通知桥合同及销毁清理通过，前台/输入守卫均通过。原 5 秒整阶段预算因串行确认耗时失败；仅批量阶段改为 30 秒有界预算，保留逐项 5 秒预算和“不增加枚举”断言。最终 32 项新增阶段约 5187ms，删除约 3674ms，不满足产品性能预期。

此为实验内的同步消息循环驱动，不能照搬到 App UI。正式接线前需异步确认、有界批次、事件重协调/背压，以及同根多视图、分组、并发重建和导航期间的检查。现有证据只证明受控顺序操作与小批量原型路径，不证明全部自动刷新已修复。普通产品 DLL、App 和预览均未修改。

真实事件来源补证：`--projected-watcher-ledger-smoke` 使用独占临时目录和实际 FileSystemWatcher，无窗口验证文件新增、改名、删除后同名重建、目录新增/删除，以及 128 个文件连续创建的所有 Created 事件均到达。测试逐条核对队列序号，离开访问后拒绝晚到事件，最后关闭 watcher 并删除自建临时目录。最终收到 264 条事件（包括允许重复的 Changed），不要求 Windows 提供固定事件总数。Release 构建及原 4096 条队列合同再验通过；尚未连接原生视图派发，也不证明极端负载下不会发生 watcher 缓冲区溢出。

2026-11-06。本批只修改 NativeProbe，不接入正式应用，不更新预览。

新增按导航访问对象隔离的 FIFO 事件队列：删除后同名重建、连续改名及大小写改名保留所有事件，同时可判断工作是否仍是相关路径的最新工作。完成旧工作只释放仍属于它的键；离开访问后永久失效并清空记录。失效判断不是文件系统对象身份验证，也不能撤销已经发出的 Shell 通知。

无窗口命令 `--projected-change-ledger-smoke` 通过：同名重建、改名链、原始大小写、旧访问拒绝、4096 条并发生产的严格序号及释放/关闭归零。原先缺少实现的编译失败记录在 `src/.state/projected-ledger-before.log`，实现后 Release 构建零错误零警告。

现有原生通知桥实验接入了队列的删除派发、行消失后的确认及真实视图销毁后待办失效检查。`src/.state/projected-ledger-native.log` 中 1029 行增删改名、精确 8KB 更新、不增加枚举、选区保留及销毁清理子断言通过。共享输入活动触发守卫，整条命令退出 1；不记完整隔离验收通过，未切换共享桌面或注入输入。

剩余门槛：真实 FileSystemWatcher 接线，过期事件的文件系统重协调，同名替换的确切对象身份，导航期间的提交时序，队列背压与突发合并，以及完整应用四窗格、同根多视图、分组验收。FIFO 暂无容量上限，只用于实验。不能简单跳过所有旧事件：创建 A 后改名 A→B，旧创建即使失效也可能需要补足原生视图状态。
